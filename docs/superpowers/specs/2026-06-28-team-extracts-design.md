# Выписки спортсменов по командам — дизайн

Дата: 2026-06-28

## Цель

Шаблон отчёта SportOrg «Выписки спортсменов по командам»: для каждой команды
печатается список её спортсменов, сгруппированный по возрастным группам, с
колонками для комиссии по допуску. Печать на A4, по одной команде с новой
страницы, сетка заполняет весь лист.

Ориентир по внешнему виду — `other/swimming-drawing` (`src/templates/admission_list.html.j2`):
A4, `table-layout: fixed`, пунктирные границы ячеек + сплошные внешние, `@page`.

## Архитектура (вариант C)

- **In-app отчёт SportOrg.** Самодостаточный **standalone HTML-шаблон** в
  `docs/templates/reports/2_выписки_по_командам_регистрация.html`. Рендерится диалогом «Создание
  протокола» (`get_text_from_file`) с контекстом `race`, `selected`, `rent_cards`,
  `name`, `version`. Данные гонки встраиваются как JSON (`{{ race | tojson }}`).
- **Вся логика и вёрстка — на client-side JS** (vanilla, без библиотек), как в
  существующих отчётах SportOrg. Печать — `Ctrl+P` в браузере.
- **Самодостаточность.** Шаблон НЕ расширяет `base_v2.html` и не зависит от
  `style_v2`/`script_v2` (они read-only и их использование нежелательно). Нужные
  мелкие хелперы (связывание `person.group`/`person.organization` по id, карта
  `Qualification`, формат даты) скопированы внутрь шаблона. На выходе — один HTML
  без внешних зависимостей (CSS/JS инлайн; при большом объёме допускается вынос в
  соседние `*.css.html`/`*.js.html` и подключение через `{% include %}`, который
  вшивает их в вывод — output остаётся standalone).
- **Размещение.** Файл живёт в `docs/templates/reports/` для разработки; в боевую
  папку (`sportorg/data/templates/reports/`) его переносит автор вручную. Чтобы
  шаблон появился в меню «Создание протокола», папка шаблонов
  (`settings.templates_path`) должна указывать на каталог, содержащий этот файл.

## Источник данных (модель SportOrg)

| Поле отчёта | Источник | Примечание |
|---|---|---|
| ФИО | `person.surname`, `person.name`, `person.middle_name` | отчество опускается, если пусто |
| Забег | `person.start_group` (целое) | маппинг ниже |
| Дата рождения | `person.birthday` (`get_birthday()`) | `дд.мм.гггг`, пусто если нет даты |
| Группа | `person.group.name` | короткое имя; пусто если группы нет |
| Квал | `Qualification[person.qual]` | пусто для `NOT_QUALIFIED`/0 |
| Чип | `person.card_number` | пусто если 0; подсветка дублей |
| Допуск | `person.national_code` (целое) | битовая маска, формат ниже |
| Примечание | `person.comment` | |
| Команда (колонтитул) | `person.organization.name` | |
| Соревнование (колонтитул) | `race.data.short_title` | «Короткое название» |

«Забег» = `start_group`, «Допуск» = `national_code` — подтверждено по GUI
(`gui/tabs/persons.py`, `gui/tabs/memory_model.py`, `entry_mass_edit.py`).

## Поток данных (в JS)

1. Связать `person.group` / `person.organization` по id (как `racePreparation`).
2. **Предрасчёт по всей гонке:** карта `count[card_number]` для определения дублей
   чипа (см. ограничение про выделение ниже).
3. Состав участников = то, что пришло в `race.persons`. Диалог «Создание протокола»
   уже применяет свои фильтры (галочка «Отправить выделенные» строит частичную
   гонку через `to_dict_partial`). Переменную `selected` поддерживаем для обратной
   совместимости.
4. Для каждой команды — в порядке `race.organizations`; команды без участников
   пропускаем:
   - участники команды группируются по `person.group`, **группы в порядке
     `race.groups`** (как во вкладке «Группы»);
   - внутри группы сортировка по ФИО (`surname`, затем `name`, затем `middle_name`;
     сравнение через `localeCompare(…, 'ru')` — корректный русский порядок, `ё` после `е`);
   - номер `№` нумеруется заново с 1 в каждой группе;
   - участники **без группы** — отдельным блоком в конце команды (поле «Группа»
     пустое); внутри блока та же сортировка и своя нумерация с 1.
5. После всех команд — блок **«Без команды»** (колонтитул слева = «Без команды») для
   участников без организации (`organization_id == null`), чтобы они не пропадали из
   отчёта. Та же группировка/сортировка через общий хелпер `buildSlots(members)`
   (его же использует `buildTeamSlots`).

## Вычисляемые поля

### Забег (из `start_group`)
- `0` → пусто
- `1`–`9` → `1`…`9`
- `11` → `роз`
- `13` → `кр`
- `91`–`99` → `×`
- остальное → пусто

### Допуск (из целого `national_code`)
Десятичные разряды — битовая маска по позициям `М П С Р Д` (= `10000 1000 100 10 1`).

Алгоритм:
1. если `national_code == 0` → пусто;
2. `s = String(national_code)`; если `s.length > 5` → пусто;
3. `s = s.padStart(5, '0')`;
4. если в `s` есть символ, отличный от `0`/`1` → пусто;
5. иначе для каждой из 5 позиций добавить `" " + (буква если '1', иначе " ")`.
   Результат — 10 символов с ведущим пробелом, моноширинный шрифт.

Примеры (проверены по образцам ТЗ):
- `11111` → `" М П С Р Д"`
- `01010` → `"   П   Р  "`
- `00101` → `"     С   Д"`
- `11211` → `""` (есть `2`)
- `0` → `""`

### Чип (из `card_number`)
- отображение: `card_number`, пусто если `0`;
- если `card_number > 0` и значение встречается у **более чем одного** участника
  всей гонки — ячейка: **серая заливка + курсив**.

**Ограничение (зафиксировано):** при включённой в диалоге галочке «Отправить
выделенные» в `race` попадает только подмножество, поэтому дубли ищутся в пределах
выделения. В обычном режиме (печать всех) это и есть вся гонка.

## Колонтитул и шапка (повторяются на каждой странице)

- **Колонтитул** — одна строка, **полужирный, 10 pt**: слева
  `organization.name`, справа `race.data.short_title` (`flex`, `space-between`).
- **Шапка столбцов** — **8 pt**.
- Основной шрифт — **10 pt, без засечек** (sans-serif). Столбец «Допуск» —
  моноширинный. Столбец «№» — **8 pt** (Примечание — обычный 10 pt).

> **Происхождение размеров.** Исходный документ — Excel, Arial 14 pt, печать в
> масштабе 70 % (физически ≈ 9.8 pt). Применяем ×0.7 с округлением: 14 pt → **10 pt**,
> 12 pt → **8 pt**. Печать в обычном режиме (100 %) совпадает с оригиналом. «Arial»
> назван лишь для оценки размера — семейства шрифтов в шаблоне (`Arial/DejaVu`
> sans-serif, `Courier New` для допуска) оставляем как есть.

## Печать и пагинация (client-side JS, вариант 1 — фиксированная высота строки)

Параметры печати: A4 portrait, поля **5 мм** со всех сторон.

### A4-боксы страниц
Каждая печатная страница — `div.page`; разрывы — средствами CSS:
```css
@page { size: A4 portrait; margin: 5mm; }
.page {
  box-sizing: border-box;
  width: 200mm;     /* 210 − 2×5 */
  height: 287mm;    /* 297 − 2×5 */
  page-break-after: always;
  overflow: hidden;
}
.page:last-child { page-break-after: auto; }
```
Структура `.page`: `div.page-header` (колонтитул) + `table` (`thead` — шапка
столбцов 8 pt; `tbody` — строки). Столбцы — `table-layout: fixed` + `<colgroup>`.

### Вместимость страницы (арифметика, без измерений DOM)
Строки фиксированной высоты, ячейки `white-space: nowrap; overflow: hidden`
(как в swimming-drawing). Тогда:
```
ROWS_PER_PAGE = floor((PAGE_H − HEADER_H − THEAD_H) / ROW_H)   // всё в мм
```
Константы (`PAGE_H = 287`, поля заданы `@page`) подбираются под шрифт 10 pt.
**`ROW_H = 6 мм`** — референсная высота строки, измеренная по распечатке исходного
Excel (линейкой). `HEADER_H`/`THEAD_H` уточняются под мелкий шрифт при реализации.
Раскладка детерминирована и совпадает на
экране и в печати.

### Алгоритм разбивки команды на страницы
Плоский список «слотов» команды (`data` / `empty`), с пустыми строками между
группами, разбивается на страницы:
```js
while (i < rows.length) {
  let take = Math.min(ROWS_PER_PAGE, rows.length - i);
  take = applyKeepMin(rows, i, take);          // см. ниже
  const slice = rows.slice(i, i + take);
  while (slice.length < ROWS_PER_PAGE)         // ДОБИВКА до низа
    slice.push({ type: 'empty' });
  pages.push(buildPage(team, slice));          // колонтитул + thead + строки
  i += take;
}
```

### Требования к раскладке
- **Заполнение всей страницы.** `slice` добивается пустыми разлинованными строками
  до `ROWS_PER_PAGE` — сетка доходит до низа листа даже при малом числе участников.
  Небольшой остаток (< `ROW_H`) внизу поглощается растяжением таблицы (`height:100%`).
  `ROWS_PER_PAGE` вычисляется с резервом `SAFETY_MM` (под горизонтальные границы между
  строками, ≈ 0.5px × N, которых нет в номинальной mm-модели), иначе последняя строка
  переливалась бы за край и обрезалась `overflow:hidden`.
- **Между группами** — одна пустая разлинованная строка (слот `empty`, такая же по
  высоте, без текста); если попадает в самый верх страницы — пропускается.
- **Keep-≥3 при разрыве группы.** Если разрыв страницы приходится внутри одной
  группы и на странице/переносе остаётся < 3 строк этой группы — разрыв отступает к
  началу группы (`applyKeepMin`, `KEEP_MIN = 3`), т.е. либо ≥3 строк по обе стороны, либо
  группа целиком переносится на следующую страницу. Группа из < 3 участников не дробится.
- **Новая команда — с новой страницы** (каждая команда — отдельный набор `.page`).

### Запасной вариант (не реализуем сейчас)
Вариант 2 — измерение высот по DOM (`getBoundingClientRect`, калибровка mm→px
через зонд) — оставлен на случай, если потребуется перенос длинных ФИО на 2 строки.
Минусы: зависимость от рендеринга браузера, сложнее добивка и keep-3, хуже тесты.

## Edge-cases

- Нет чипа (`0`) → «Чип» пусто, в подсчёте дублей не участвует.
- `national_code == 0` или не проходит формат (длина > 5 / цифра ≠ 0/1) → «Допуск» пусто.
- Нет даты рождения / квалификации / отчества → соответствующее поле пусто.
- Участник без группы → блок «без группы» в конце команды, поле «Группа» пустое.
- Участник без организации → блок **«Без команды»** в конце отчёта (общий хелпер `buildSlots`).
- Команда без участников (после фильтра диалога) → страница не создаётся.
- Группа из 1 участника не дробится между страницами.
- Маркеры «вне зачёта» (`o/c`) не добавляются (в ТЗ нет).

## Тестирование и превью

- **Превью при разработке.** Временный `uv run`-скрипт грузит
  `data/2024-01-28_relay_international.json` через **десериализатор SportOrg**
  (`sportorg/modules/backup/json.py`), формирует контекст (`race = race.to_dict()`,
  `name`, `version`, `rent_cards`, `selected`), рендерит шаблон (Jinja,
  searchpath = `docs/templates/reports`) в HTML и открывает в браузере. Раздачу
  сырого `json.load` не использовать.
- **Авто-тест (pytest).** Рендер шаблона на образце без ошибок + проверка ключевых
  токенов (имена команд, строки допуска для известных `national_code`, маппинг
  Забега). JS-вёрстку (пагинация, добивка, keep-2) проверяем визуально в браузере.
- Временные python-файлы (превью/тест) коммитятся, удаляются автором вручную.
