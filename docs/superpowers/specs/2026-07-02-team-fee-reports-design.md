# Выписки по командам со стартовым взносом — дизайн

Дата: 2026-07-02

## Цель

Два новых шаблона отчёта SportOrg на основе
`2_выписки_по_командам_регистрация.html`: тот же покомандный список спортсменов на
A4, но вместо колонки «Допуск» — расчёт **стартового взноса** (плюс аренда чипа) на
каждого участника и **сводка по команде** под таблицей. Документ служит для
регистрационной комиссии — по нему команда платит.

Два варианта отличаются только формулами взноса ЧСФО/ПСФО:

| Файл | Вариант | ЧСФО | ПСФО | РС | Чип |
|---|---|---|---|---|---|
| `2_выписки_по_командам_взнос.html` | 2 (фикс.) | 1650 ₽ (фикс.) | 1200 ₽ (фикс.) | 150/200 ₽ × дни участия | 100/150 ₽ (бк) × дни участия |
| `2_выписки_по_командам_взнос_10процентов.html` | 3 (подневный) | 550 ₽/день участия + 55 ₽/день неучастия | 400 ₽/день участия + 40 ₽/день неучастия | 150/200 ₽ × дни участия | 100/150 ₽ (бк) × дни участия |

День неучастия в варианте 3 = 10 % от дневного тарифа (55 = 10 % от 550,
40 = 10 % от 400) — отсюда суффикс `_10процентов` в имени файла. РС и аренда чипа в
варианте 3 **не меняются**.

## Архитектура

- **Оба файла — клоны** `2_выписки_по_командам_регистрация.html`: самодостаточный
  standalone HTML, данные гонки как `{{ race | tojson }}`, вся логика/вёрстка на
  vanilla JS без библиотек, печать `Ctrl+P`. Те же теговые секции
  (`[helpers]`, `[transforms]`, `[render]`, `[pagination]`, `[selftest]`, `[main]`),
  та же A4-пагинация (вариант 1 — фиксированная высота строки `ROW_H = 6 мм`).
- **Общая база — 95 % кода.** Отличие вариантов 2 и 3 — только содержимое секции
  `[fee-config]` (тарифы ЧСФО/ПСФО). Остальное идентично. Две спеки не нужны — один
  дизайн, два файла.
- **Размещение.** Файлы живут в `docs/templates/reports/` для разработки; в боевую
  папку их переносит автор вручную (как с выписками).

## Источник данных (модель SportOrg)

Колонки данных наследуются из выписок; убрана «Допуск», добавлена «Взнос».

| Поле отчёта | Источник | Примечание |
|---|---|---|
| ФИО | `person.surname`, `person.name`, `person.middle_name` | отчество опускается, если пусто |
| Забег | `person.start_group` (целое) | маппинг из выписок |
| Дата рождения | `person.birthday` | `дд.мм.гггг`, пусто если нет |
| Группа | `person.group.name` | ключ тарифа; пусто → «без группы» |
| Квал | `Qualification[person.qual]` | пусто для `NOT_QUALIFIED`/0 |
| Чип | `person.card_number` | пусто если 0; подсветка дублей |
| **Комментарий** | `person.comment` | переезжает на место «Допуска»; из него парсится код участия `С:` |
| **Взнос** | вычисляется (см. ниже) | стартовый взнос + аренда чипа |
| Аренда чипа | `person.is_rented_card` (bool) | 100 ₽ (или 150 ₽ при `бк` в комментарии) × дни участия |
| Команда (колонтитул) | `person.organization.name` | |
| Соревнование (колонтитул) | `race.data.short_title` | |

Поля подтверждены по `sportorg/models/memory.py`: `is_rented_card`, `comment`,
`group`, `card_number`, `start_group` — атрибуты `Person`.

## Столбцы

Из выписок убираем «Допуск» (`national_code`, `formatDopusk`), «Примечание»
переименовываем в **«Комментарий»** и ставим на место «Допуска», в конец добавляем
**«Взнос»**. Всего колонок остаётся 9. Ширины «Комментария» и «Взноса» подбираются
при реализации (взнос узкий, ~6–8 %; остаток — комментарий).

| key | Заголовок | Гор. выравнивание |
|---|---|---|
| `index` | № | по правому краю, 8 pt |
| `fio` | Фамилия, имя, отчество | по левому краю |
| `zabeg` | Забег | по центру |
| `birth` | Дата рождения | по центру |
| `group` | Группа | по центру |
| `qual` | Квал | по центру |
| `chip` | Чип | по центру |
| `note` | Комментарий | по левому краю |
| `fee` | Взнос | **по правому краю** (денежная сумма) |

Прочая типографика (шрифты 10/8 pt, колонтитул, подсветка дублей чипа) — как в
выписках.

## Конфигурация взноса — секция `[fee-config]`

Вся арифметика и константы — в JS, в **одном заметном блоке наверху скрипта**, с
шапкой-комментарием «ПРАВЬ ЗДЕСЬ». Цель — чтобы в готовом HTML тарифы правились
руками без чтения остального кода.

`TARIFF` организован **по категориям** (ключ = вид соревнований/подтариф), у каждой
— `name` (метка для сводки), список `groups` (ТОЧНЫЙ белый список имён групп) и поле
тарифа. **Имя поля тарифа само кодирует семантику** (нет отдельного флага `flat`):

| поле | смысл | взнос |
|---|---|---|
| `tariffTotal` | за **все** дни (фиксированный) | `tariffTotal` |
| `tariffPerDay` | за **день участия** | `tariffPerDay × дни_участия` |
| `tariffPerDay` + `tariffPerAbsentDay` | день участия **и** день неучастия | `tariffPerDay × дни_участия + tariffPerAbsentDay × дни_неучастия` |

Поиск: группа → категория, чья `groups` её содержит (строим обратный индекс
`group → категория` при старте). Группа, которой нет ни в одной `groups`, —
незнакомая (взнос 0 + подсветка + строка в сводке).

### Вариант 2 (`..._взнос.html`)

```js
// ======================= [fee-config] ПРАВЬ ЗДЕСЬ =======================
var EVENT_DAYS = 3;            // всего дней соревнований (константа)

// Аренда чипа за день участия. Два тарифа: обычный и «бк» (если в комментарии есть маркер).
var CHIP_PER_DAY    = 100;     // обычный чип
var CHIP_PER_DAY_BK = 150;     // чип «бк» (комментарий содержит CHIP_BK_MARK)
var CHIP_BK_MARK    = 'бк';    // маркер «бк» в комментарии (поиск без учёта регистра)

var TARIFF = {
  'ЧСФО':   { name: 'ЧСФО', tariffTotal: 1650, groups: ['МА', 'ЖА'] },
  'ПСФО':   { name: 'ПСФО', tariffTotal: 1200, groups: ['М18','Ж18','М16','Ж16','М14','Ж14'] },
  'РС-200': { name: 'РС',   tariffPerDay: 200,  groups: ['М35','Ж35','М45','Ж45','М55','Ж55','М65+','Ж65+'] },
  'РС-150': { name: 'РС',   tariffPerDay: 150,  groups: ['М12','Ж12','М10','Ж10'] }
};
// =======================================================================
```

> **Про «М65+».** Белый список — точный: имя в `groups` должно буквально совпасть с
> `group.name` в гонке. Если реальная группа называется иначе (`М65`, `М70`…), имя
> правят вручную. Незнакомые группы отчёт подсвечивает и выносит в сводку отдельной
> строкой (взнос по ним не считается) — расхождение имён сразу видно.

### Вариант 3 (`..._взнос_10процентов.html`)

Отличается только тем, что ЧСФО и ПСФО становятся подневными: поле `tariffTotal`
заменяется на пару `tariffPerDay` + `tariffPerAbsentDay` (день неучастия ≈ 10 % от
дня участия — отсюда имя файла). РС и `CHIP_PER_DAY` — без изменений. Явные ставки
(не «10 % в коде») — так их проще править:

```js
var TARIFF = {
  'ЧСФО':   { name: 'ЧСФО', tariffPerDay: 550, tariffPerAbsentDay: 55, groups: ['МА', 'ЖА'] },
  'ПСФО':   { name: 'ПСФО', tariffPerDay: 400, tariffPerAbsentDay: 40, groups: ['М18','Ж18','М16','Ж16','М14','Ж14'] },
  'РС-200': { name: 'РС',   tariffPerDay: 200,  groups: ['М35','Ж35','М45','Ж45','М55','Ж55','М65+','Ж65+'] },
  'РС-150': { name: 'РС',   tariffPerDay: 150,  groups: ['М12','Ж12','М10','Ж10'] }
};
```

## Код участия и подсчёт дней

Из `person.comment` парсится **код участия** — токен после `С:` (или латинской `C:`):

- regex `/[СC]:(\S+)/` — берём непробельную последовательность сразу за `С:`
  (`"С:1?3 в/к"` → `"1?3"`; лишний текст игнорируется);
- **дни участия** = число цифр в токене, ограниченное `EVENT_DAYS`
  (цифра = участвует в этот день; `?`, `-`, `x` и любой не-цифровой символ = не
  участвует);
- **если код `С:` не найден** → участник считается участвующим **все** `EVENT_DAYS`
  дней (правило подтверждено);
- **дни неучастия** = `EVENT_DAYS − дни участия` (нужно варианту 3).

Примеры (`EVENT_DAYS = 3`):

| comment | дни участия | дни неучастия |
|---|---:|---:|
| `С:123` | 3 | 0 |
| `С:1?3` / `С:?23` / `С:12x` | 2 | 1 |
| `С:??3` | 1 | 2 |
| `С:???` | 0 | 3 |
| (нет кода) | 3 | 0 |
| `С:1?3 в/к` | 2 | 1 |

## Вычисление взноса на человека

Формула — одна для обоих вариантов, ветвится по **наличию полей** в записи
категории (`t` = категория группы участника):

```
days_in  = дни участия
days_out = EVENT_DAYS − days_in

startFee =
  задан t.tariffTotal          -> t.tariffTotal                                   // за все дни (ЧСФО/ПСФО вар.2)
  задан t.tariffPerAbsentDay   -> t.tariffPerDay*days_in + t.tariffPerAbsentDay*days_out  // участие+неучастие (вар.3)
  иначе (только tariffPerDay)  -> t.tariffPerDay*days_in                          // за день участия (РС)

chipRate = comment содержит CHIP_BK_MARK (без учёта регистра) ? CHIP_PER_DAY_BK : CHIP_PER_DAY
chipFee  = person.is_rented_card ? chipRate * days_in : 0

Взнос (колонка) = startFee + chipFee        // подтверждено: стартовый + аренда чипа
```

- Колонка «Взнос» = **стартовый взнос + аренда чипа** конкретного участника. Значит
  **сумма колонки по команде = «Итого» команды**.
- Незнакомая группа (нет ни в одной `groups`) → `startFee = 0`, участник подсвечивается,
  учитывается в сводке отдельной строкой; аренда чипа при этом всё равно считается.
- Аренда чипа считается по `is_rented_card` независимо от наличия `card_number`.

## Сводка по команде (под таблицей)

Сводка формируется **для каждой команды** (общий итог по всему соревнованию не
делаем — подтверждено). Строки сводки:

```
ЧСФО: 10 человек, 16 500 ₽          (3 дня: N чел; 2 дня: M; 1 день: K)
ПСФО: 12 человек, 14 400 ₽          (…)
РС (200 ₽/день): 5 человек, 3 000 ₽ (…)
РС (150 ₽/день): 8 человек, 3 600 ₽ (…)
Аренда чипов: 5 чипов, 1 500 ₽
[неизвестные группы: N чел — взнос не посчитан]   ← только если есть
——————————————————————
Итого: 39 000 ₽
```

- **Категории** ЧСФО, ПСФО и **две строки РС** (200 ₽ ветераны/взрослые, затем
  150 ₽ дети — порядок как в примере ТЗ). Суммы категорий — **только стартовый
  взнос** (без чипа).
- **Аренда чипов** — отдельная строка: число арендованных чипов и сумма
  (Σ `chipFee` по команде). Если в команде есть чипы обоих тарифов — хвост с
  разбивкой (`100 ₽: N`, `150 ₽ (бк): M`).
- **Подневная детализация** (опция ТЗ, включаем): для каждой категории —
  «сколько человек на 3/2/1 день». Для фикс-категорий информативно; для РС объясняет
  сумму. Формат — компактный хвост строки категории.
- **Итого** = Σ стартовых взносов всех категорий + Σ аренды чипов = Σ колонки
  «Взнос». Разделительная линия перед «Итого».
- Денежные суммы — с разделением тысяч неразрывным пробелом (`16 500 ₽`).

## Размещение сводки и пагинация

Сводка встраивается **строками той же таблицы** (после строк данных команды), чтобы
переиспользовать проверенную построчную пагинацию из выписок и буквально оказаться
«ниже таблицы»:

- после `data`-слотов команды добавляется разделитель + слоты `type:'summary'` (по
  одному на строку сводки), каждый ≈ высотой строки;
- слоты сводки рендерятся полноширинными строками (`<tr class="row-summary"><td
  colspan="9">…</td></tr>`), участвуют в подсчёте `ROWS_PER_PAGE`;
- **сводка не разрывается**: если блок сводки не помещается в остаток страницы —
  переносится целиком на новую страницу (простое keep-whole правило поверх
  существующего `applyKeepMin`); блок маленький (~6–10 строк), у края страницы
  оказывается редко;
- на странице со сводкой строки сводки не растягиваются добивкой `height:100%`
  (фикс. высота), слак поглощают пустые строки-добивки — деталь реализации.

Прочая пагинация (A4-боксы, `ROWS_PER_PAGE`, `SAFETY_MM`, `KEEP_MIN`, добивка до
низа, новая команда с новой страницы, блок «Без команды») — без изменений из
выписок.

## Edge-cases

- Нет кода `С:` → все `EVENT_DAYS` дней участия (правило ТЗ).
- Код целиком из не-цифр (`С:???`) → 0 дней участия; РС/чип = 0; фикс-категории
  платят полный флэт (взнос «независимо от дней»).
- Код длиннее `EVENT_DAYS` → дни участия обрезаются до `EVENT_DAYS`.
- Незнакомая группа → взнос 0 + подсветка + строка в сводке; чип считается.
- Нет группы (`group == null`) → блок «без группы»; трактуется как незнакомая для
  взноса (0 + подсветка).
- Аренда без чипа (`is_rented_card && card_number == 0`) → чип считается по флагу.
- `бк` в комментарии + аренда → тариф чипа `CHIP_PER_DAY_BK` (150) вместо 100; без
  флага аренды `бк` игнорируется. Маркер ищется во всём комментарии, регистр не важен.
- Команда без участников → страниц нет.
- Наследуются edge-cases выписок (нет чипа/квала/даты/отчества; дубли чипа; keep-≥3;
  «Без команды»).

## Тестирование и превью

- **Превью при разработке.** Временный `uv run`-скрипт грузит образец гонки через
  **десериализатор SportOrg** (`sportorg/modules/backup/json.py`), рендерит оба
  шаблона (Jinja, searchpath = `docs/templates/reports`) и открывает в браузере.
  Сырой `json.load` не используем.
- **Авто-тест (pytest).** Рендер обоих шаблонов без ошибок + проверка ключевых
  токенов: заголовок «Взнос», отсутствие «Допуск», строки сводки, известные суммы на
  синтетических данных. Ядро расчёта (`feeFor`, `parseDays`) проверяется JS-selftest
  (баннер `SELFTEST OK/FAIL`, как в выписках) с векторами из таблиц выше.
- **JS-selftest** обязателен: векторы `parseDays` (коды → дни участия/неучастия) и
  `feeFor` (группа+дни+чип → взнос) для обоих вариантов.
- Временные python-файлы (превью/тест) коммитятся, удаляются автором вручную.
